> 테스트 일시: 2026-03-16
> 테스트 방법: Playwright 브라우저 자동화로 실제 KDA 2기 데이터 (8명, 3팀, 9개 카테고리) 기반 전체 워크플로우 수행

## 마찰 포인트 상세

---

### 🔴 #1 — `input_scope: 'team'` 팀 입력 모드 동작 안 함 *(신규)*

**상황**: 1차/2차 프로젝트의 "팀 평가" sub-category (`input_scope: 'team'`) 진입
**문제**:
- "팀별" 배지는 표시되나 테이블에 **팀 3개가 아닌 학생 8개 행**이 표시됨
- 점수 저장 시 teamId가 아닌 **studentId 키로 저장** (`raw_scores[catId][studentId]`)
- 같은 팀 학생들에게 동일 점수가 자동 복사되지 않음
- 팀 단위 점수 입력이 사실상 **불가능한 상태**

**기대 동작**: 팀 행 3개 표시, 팀당 1회 입력 → 해당 팀 멤버 전원에게 동일 점수 적용
**영향**: 1차/2차 프로젝트의 팀 평가 항목 전체가 무의미. KDA 운영 시 가장 핵심 기능.

---

### 🔴 #2 — `final_formula` 미설정 시 복합 계산 전체 실패 *(신규)*

**상황**: `scoring_method: 'composite'` 카테고리 생성 직후 (formula 미입력 상태)
**문제**:
- formula 기본값 없음 → 빈 문자열 파싱 → `unexpected TEOF: EOF` 오류
- 계산 엔진이 모든 학생에 대해 `{ calculated: 0, error: "unexpected TEOF: EOF" }` 반환
- 전체 평가 요약, 사이드바 총점 모두 0 표시
- **오류 메시지가 UI에 전혀 표시되지 않아** 사용자는 집계가 안 되는 이유를 알 수 없음

**기대 동작**: 기본 formula 자동 생성 (`_cat0 + _cat1 + ...`) 또는 formula 미설정 시 경고 표시
**영향**: 복합 카테고리 생성 후 formula 설정을 별도로 하지 않으면 항목 전체가 무효화됨

---

### 🔴 #3 — 기수 생성 후 자동 이동 없음

**상황**: 홈에서 "새 기수 만들기" → 이름 입력 → 생성 버튼 클릭
**문제**: 다이얼로그가 닫히고 홈 화면의 카드 목록만 갱신됨. 사용자가 직접 생성한 기수 카드를 다시 클릭해야 진입 가능.
**기대 동작**: 생성 직후 자동으로 해당 기수 대시보드로 이동
**영향**: 첫 사용자 이탈 가능성 높음 — 생성이 성공했는지, 다음에 무엇을 해야 하는지 불명확

---

### 🔴 #4 — 빈 상태 화면에 온보딩 없음

**상황**: 기수 생성 후 "평가 항목" 탭 진입
**문제**: 학생도, 카테고리도 없는 빈 총점 테이블만 표시. "항목 관리" 버튼이 기본으로 **접혀 있어** 추가 방법 자체를 발견하기 어려움.
**기대 동작**: 빈 상태에서 "학생을 먼저 추가하세요 →", "평가 항목을 추가하세요 →" 같은 안내 메시지 또는 "항목 관리" 자동 펼침
**영향**: 처음 사용자는 무엇을 해야 할지 모름

---

### 🟡 #5 — 복합 카테고리 formula 변수명 규칙 불명확 *(신규)*

**상황**: 1차/2차 프로젝트 `⚙ 설정` → "최종 공식" 입력
**문제**:
- placeholder: `(sub1 + sub2) * 15 / 100` — `sub1`, `sub2`라는 변수명 암시
- 실제 엔진 변수명: `_cat0`, `_cat1`, `_cat2` (인덱스 기반, 소스 코드에서만 확인 가능)
- 한글 카테고리명(`팀_평가`, `개인_발표`)도 변수로 사용 가능하나 공백을 `_`로 치환해야 하는 규칙이 UI에 전혀 설명되지 않음
- formula를 올바르게 작성하려면 내부 구현 지식 필요

**기대 동작**: sub-category 이름 목록과 사용 가능한 변수명을 설정 패널 안에 표시
  예: `사용 가능한 변수: _cat0 (팀 평가), _cat1 (개인 발표)`
**영향**: formula 설정 사실상 불가 → 복합 카테고리 전체가 무력화

---

### 🟡 #6 — 복합 카테고리 설정 경로 불명확 *(신규)*

**상황**: `scoring_method: 'composite'` 카테고리 생성 후 점수 집계 설정
**문제**:
- formula 입력 위치: 해당 카테고리 eval 페이지 → `⚙ 설정` (기본 접힘) → 최종 공식 입력
- 이 경로가 UI에서 전혀 안내되지 않음
- 카테고리 추가 다이얼로그에서 `composite` 방식 선택 시 formula 설정 step이 없음
- formula 없이 저장 → 집계 실패 → 0점 표시 → 원인 불명

**기대 동작**: composite 카테고리 생성 직후 formula 입력 단계 유도, 또는 formula 미설정 시 카드/헤더에 경고 표시
**영향**: 복합 카테고리 = 별도 설정 단계가 반드시 필요함을 모르는 사용자는 0점만 보게 됨

---

### 🟡 #7 — `▶ -` 표기 의미 불명확 *(신규)*

**상황**: 1차/2차 프로젝트 중간 집계 페이지 — sub-category 값 셀
**문제**: sub-category에 점수 미입력 상태를 `▶ -`로 표시. `-`가 0점인지, null인지, 오류인지 구분 불가.
  점수 입력 후에도 formula 오류 시 `▶ -` → `▶ 0.0`으로 바뀌어 실제 입력이 반영됐는지 불명확.
**기대 동작**: 미입력 = `▶ -`, 입력됨 = `▶ 6.0`, 계산 오류 = `▶ ⚠ 오류` 로 구분
**영향**: 데이터 입력 완료 여부를 시각적으로 확인 불가

---

### 🟡 #8 — "◀ 전체 평가" 버튼 및 카테고리 간 이동 버튼 없음

**상황**: 카테고리 점수 입력 후 전체 페이지로 복귀
**문제**: "◀ 전체 평가"라는 버튼이 있으나 "뒤로" 또는 "나가기" 의미인지 불명확.
한 카테고리 입력 완료 후 다음 카테고리로 이동하는 **직접 버튼이 없음** — 전체 요약으로 돌아간 후 다시 다음 카테고리 셀을 클릭해야 함.
**개선안**: "다음 카테고리 →" 버튼 추가, 또는 상단 탭/진행 표시기
**영향**: 여러 카테고리 순서대로 입력 시 불필요한 왕복 탐색 발생

---

### 🟢 #9 — 순위 소수점 표시

**상황**: 전체 평가 요약 테이블 및 사이드바
**문제**: 순위가 `1.0`, `8.0` 등 소수점 형태로 표시됨
**기대 동작**: 순위는 정수 표시 (`1`, `8`)
**영향**: 시각적 어색함, 신뢰도 감소 느낌

---

### 🟢 #10 — 전체 평가 요약 테이블 이름 컬럼 미고정

**상황**: 9개 카테고리 + 가산점 2개 + 수정 + 총점 + 순위 = 14개 컬럼 (1차/2차 프로젝트 포함)
**문제**: 카테고리가 늘어날수록 테이블이 가로로 매우 길어짐. 현재 가로 스크롤로 처리되나, 이름 컬럼이 고정되어 있지 않아 오른쪽으로 스크롤 시 학생 이름이 사라짐.
**개선안**: 이름 컬럼 `position: sticky left` 고정
**영향**: 카테고리 7개 이상 시 테이블 이름 컬럼 가시성 저하

## 복합 집계 워크플로우 마찰 흐름 *(신규 섹션)*

```
1차/2차 프로젝트 점수 입력 경로 (현재 상태)

[전체 평가] → 1차 프로젝트 셀 클릭
  ↓
[1차 프로젝트 중간 레벨]
  - "팀 평가" 셀 클릭 → [팀 평가 leaf]
      ❌ 팀 행 3개 대신 학생 8명 행 표시 (input_scope 무시)
      ❌ studentId로 저장됨 (팀 집계 불가)
  - "개인 발표" 셀 클릭 → [개인 발표 leaf]
      ✅ 학생별 입력 가능
      ❌ 점수 입력해도 "점수 (7)" 컬럼에 값이 안 나타남 (formula 오류)
  ↓
[1차 프로젝트 중간 레벨] 복귀
  - 모든 셀 "▶ -" (집계 안됨)
  - formula 설정 필요 → ⚙ 설정 클릭 (접혀있음) → "최종 공식" 입력
      ❌ 변수명 규칙 설명 없음 (_cat0, _cat1 사용해야 함)
      ❌ formula 저장 전까지 집계 0
  ↓
formula "_cat0 + _cat1" 입력 후 저장 → 겨우 집계 동작
  ✅ 개인 발표 점수(6, 5) 반영됨
  ❌ 팀 평가 점수는 studentId 저장이라 여전히 0
```

## 워크플로우별 소요 시간 추정 (8명, 1차 프로젝트 포함)

| 단계 | 현재 인터랙션 수 | 개선 후 예상 |
|------|----------------|-------------|
| 기수 생성 | 4 (버튼 + 이름 + 생성 + 카드 재클릭) | 3 (자동 이동) |
| 학생 추가 (8명 일괄) | 3 | 3 |
| 팀 생성 (3팀) | 9 | 9 |
| 팀 배정 (8명) | 16 | 4~8 (다중선택) |
| 카테고리 추가 (9개) | 27+ | 9~12 (인라인) |
| 점수 입력 (7개 단순 카테고리 × 8명) | ~120 | ~120 (동일) |
| 복합 카테고리 formula 설정 (2개) | 현재 불가 (오류) → 설정 시 6단계 × 2 | 생성 시 자동 생성 |
| 복합 팀 평가 입력 (2개 × 3팀) | 현재 불가 (기능 broken) | 팀 행 입력 6번 |

## 개선 우선순위 권고

### 🔴 즉시 수정 필요 (기능 broken)
1. **[P0]** `input_scope: 'team'` 구현 — DataTable에서 팀 행 렌더링, teamId로 저장, 팀원 동일 점수 적용
2. **[P0]** composite formula 기본값 자동 생성 — `_cat0 + _cat1 + ...` 또는 sub-category 합산
3. **[P0]** formula 오류 시 UI 경고 표시 — 현재 silent fail로 0점만 나타남

### 🟡 사용성 개선 (UX 마찰)
4. **[P1]** composite 카테고리 생성 flow에 formula 설정 단계 포함
5. **[P1]** formula 설정 패널에 변수명 목록 표시 (`_cat0 = 팀 평가`, `_cat1 = 개인 발표`)
6. **[P1]** 기수 생성 후 자동 이동
7. **[P2]** 빈 상태 온보딩 안내
8. **[P2]** `▶ -` vs `▶ 0.0` vs `▶ ⚠` 구분 표기

### 🟢 폴리시 (낮은 우선순위)
9. **[P3]** 순위 정수 포맷
10. **[P3]** 이름 컬럼 sticky 고정
