## Focal Point

The primary visual anchor of the modified DataTable view is the **weight row** -- the editable row pinned between the table header and the first data row. Its shared header-level background (`--color-table-header-bg`) and compact number inputs draw the administrator's eye to per-column weight configuration before scanning student score data below.

## Interaction Contracts

### 1. Weight Row

**Trigger:** Displayed on all non-root category views where `tableColumns.length > 0` AND scoring method is NOT a deprecated method (composite, formula, boolean, boolean_with_deduction, rank_differential).

**Condition change from current:**
- Current: `!isRoot && tableColumns.length > 0 && !isComposite`
- Phase 1: `!isRoot && tableColumns.length > 0 && !isDeprecatedMethod(category.scoring_method)`

**Visual contract:**
- Rendered as a special row between the table header and the first data row
- Background: `--color-table-header-bg` (same as header)
- First cell: label text `가중치` (for average/user_input) or `배수` (for sum), styled `text-xs font-semibold text-muted-foreground`
- Each column cell: editable `<Input>` of type number, compact sizing (`h-7 w-16 text-center text-xs`), default value `1`
- Weight input accepts positive numbers only. Empty input saves as `1` (default).

**Behavior:**
- Changing a weight triggers `onWeightChange(colId, weight)` callback
- Both `input_fields` and `sub_categories` columns show weight inputs
- Weight change persists to config via existing `handleWeightChange` in EvalNode
- Score recalculates immediately after weight save (via WebSocket `data-changed` event)

### 2. Rank Column (Always Visible)

**Trigger:** All non-root category views, regardless of scoring method.

**Condition change from current:**
- Current: Only shown for `RANK_DIFFERENTIAL` method
- Phase 1: Always shown for all methods

**Visual contract:**
- Column header: `순위`
- Column alignment: center
- Cell content: integer rank number, plain text, `text-sm` size
- Tie handling: Standard competition ranking (1, 1, 3 -- ties share rank, next rank skips)
- Null/empty scores: rank displays as `-`

**Behavior:**
- Rank computed from the `calculated` score (or override if present) for each student in the category
- Rank updates when any score in the category changes
- Sortable via existing `SortHeader` click pattern

### 3. Method Selector Restriction

**Trigger:** `InlineSettings` component method dropdown.

**Visual contract for NEW categories (v1 methods only):**
- Dropdown shows exactly 3 options: `평균`, `합산`, `사용자입력`
- Maps to engine keys: `weighted_average`, `sum_divide`, `user_input`

**Visual contract for EXISTING categories with deprecated methods:**
- Method name displayed as a read-only `<Badge>` (not a dropdown)
- Badge text: existing `METHOD_LABELS[method]` value (e.g., `복합`, `공식`, `Boolean`)
- Badge variant: `secondary` with `text-muted-foreground`
- Tooltip on hover: `이 평가 방식은 더 이상 새로 생성할 수 없습니다`
- No ability to change back to deprecated method once changed to v1 method

### 4. Unified FieldManager

**Trigger:** Non-root category views, inside the collapsible settings panel.

**Visual contract:**
- Single collapsible section labeled `필드 관리` (existing pattern)
- Two sub-sections inside, always rendered (either can be empty):
  1. **입력 필드** section: list of input_fields with add/delete/reorder controls
  2. **하위 항목** section: list of sub_categories with add/delete/reorder controls
- Section divider: `<Separator>` between the two sub-sections when both have items
- Add button for input fields: `+ 입력 필드 추가` (existing pattern)
- Add button for sub-categories: `+ 하위 항목 추가`
- Each sub-category row: name input + method selector (v1 methods only) + delete button

**Behavior:**
- Adding a sub-category calls new `addSubCategory` API endpoint
- Adding an input field uses existing input field creation pattern
- Both sections are independently scrollable if content overflows
- D-07 contract: a node can have BOTH input_fields and sub_categories simultaneously

### 5. Override (No Visual Change)

Per D-06: Override cells are NOT visually distinguished from calculated cells. No badge, no color change, no icon. The existing override input column continues to work as-is.

**Behavior change:** Override now propagates correctly through recursive tree calculation. This is an engine change, not a UI change. The override input in DataTable remains unchanged.

### 6. Empty Node Display

Per D-09 and Claude's Discretion resolution:

**Visual contract:**
- A node with no `input_fields` and no `sub_categories` renders the page with:
  - Breadcrumb navigation (if depth >= 2)
  - InlineSettings (collapsed by default)
  - FieldManager (showing both empty sections with add buttons)
  - NO DataTable (no columns to render)
- Score for students in an empty node: display as blank (`-` / null)
- No special "empty state" banner. The FieldManager add buttons serve as the call to action.
